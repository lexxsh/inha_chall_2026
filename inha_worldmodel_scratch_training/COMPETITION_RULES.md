# 인하 인공지능 챌린지 2026 — 평가, 제출 및 데이터 구조 요약

> 본 문서는 대회 안내 내용을 소스 저장소에 포함하기 쉽도록 정리한 요약본입니다.  
> 규정 해석이 필요한 경우 대회 공식 공지와 최신 원문을 우선합니다.

## 1. 과제 개요

본 대회는 **평가 샘플별 초기 이미지와 행동 조건을 입력받아 미래 영상을 생성하는 과제**입니다.

각 평가 샘플에는 다음 정보가 제공됩니다.

- 초기 이미지: `data/eval/images/sample_*.png`
- 행동 조건: `data/eval/actions/sample_*.npy`

참가자는 초기 이미지와 동일한 샘플 ID를 가진 행동 조건을 함께 사용하여 영상을 생성해야 합니다.

생성 영상은 다음 형식으로 저장합니다.

```text
sample_000000.mp4
sample_000001.mp4
...
```

생성한 영상은 공식 `submission_kit`을 사용하여 제출용 CSV로 변환해야 합니다.

## 2. 리더보드 평가

### 2.1 점수 산식

```text
Score
= 0.3 × DINO Component
+ 0.3 × Video Feature Component
+ 0.4 × Action Component
```

> **Score가 0에 가까울수록 좋은 점수입니다.**

### 2.2 평가 항목

| 항목 | 가중치 | 평가 내용 | 계산 기준 |
|---|---:|---|---|
| DINO Component | 0.3 | 생성 영상의 프레임 단위 시각적 특징이 정답 데이터와 얼마나 유사한지 평가 | 공식 제출킷에서 추출한 feature와 정답 feature 간 Cosine Distance |
| Video Feature Component | 0.3 | 생성 영상의 전체적인 시공간 영상 특징이 정답 데이터와 얼마나 유사한지 평가 | 공식 제출킷에서 추출한 feature와 정답 feature 간 Cosine Distance |
| Action Component | 0.4 | 생성 영상이 주어진 행동 조건을 얼마나 잘 반영했는지 평가 | 생성 영상에서 추정한 행동 정보와 기준 행동 정보 간 MAE |

### 2.3 Public / Private 리더보드

| 구분 | 평가 범위 |
|---|---:|
| Public Score | 전체 `eval` 데이터 중 사전 샘플링된 30% |
| Private Score | 전체 `eval` 데이터 중 나머지 70% |

최종 평가는 **Private Score 100% 정량 평가**로 진행됩니다.

### 3.1 디렉터리 및 파일 설명

#### `data/train/`

모델 학습에 사용할 수 있는 로봇 조작 학습 데이터입니다.

다음 정보가 포함될 수 있습니다.

- 영상
- 행동 정보
- 메타 정보

대회에서 제공한 `train` 데이터만 모델 학습에 사용할 수 있습니다.

#### `data/eval/images/`

평가 샘플별 초기 이미지가 저장되어 있습니다.

```text
sample_000000.png
sample_000001.png
...
```

각 이미지는 동일한 샘플 ID의 행동 조건 파일과 함께 사용해야 합니다.

#### `data/eval/actions/`

평가 샘플별 행동 조건 파일이 저장되어 있습니다.

```text
sample_000000.npy
sample_000001.npy
...
```

`images/`와 `actions/`의 파일은 동일한 샘플 ID를 기준으로 대응됩니다.

예:

```text
data/eval/images/sample_000123.png
data/eval/actions/sample_000123.npy
```

#### `submission_kit/`

참가자가 생성한 MP4 영상을 리더보드 제출용 CSV로 변환하는 공식 제출 도구입니다.

일반적인 제출 흐름은 다음과 같습니다.

1. `eval` 샘플별 영상 생성
2. 생성 영상을 `submission_kit/input_videos/`에 저장
3. `make_submission_csv.py` 실행
4. 생성된 CSV를 리더보드에 제출

#### `submission_kit/input_videos/`

평가 데이터에 대해 생성한 영상을 저장하는 폴더입니다.

파일명은 반드시 다음 형식을 따라야 합니다.

```text
sample_000000.mp4
```

파일명에 포함된 샘플 ID는 평가 이미지와 행동 조건의 샘플 ID와 일치해야 합니다.

예:

```text
data/eval/images/sample_000123.png
data/eval/actions/sample_000123.npy
submission_kit/input_videos/sample_000123.mp4
```

#### `submission_kit/make_submission_csv.py`

`input_videos/`에 저장된 영상을 평가용 feature로 변환하고 제출용 CSV를 생성하는 공식 스크립트입니다.

제출 CSV는 반드시 이 스크립트를 통해 생성해야 합니다.

#### `submission_kit/sample_submission.csv`

리더보드 제출 CSV의 형식 예시입니다.

이 파일은 제출 형식을 확인하기 위한 용도이며, 실제 제출 파일은 공식 `make_submission_csv.py`를 통해 생성해야 합니다.

#### `submission_kit/requirements.txt`

공식 제출킷 실행에 필요한 Python 패키지와 버전 정보가 포함된 파일입니다.

#### `submission_kit/README.md`

공식 제출킷 설치 및 실행 방법이 포함된 문서입니다.

#### `baseline/`

기본적인 영상 생성 및 제출 파일 생성 과정을 확인할 수 있는 베이스라인 코드입니다.

#### `baseline/baseline.ipynb`

베이스라인 모델 실행, 추론 및 제출 파일 생성 흐름을 확인할 수 있는 Jupyter Notebook입니다.

#### `baseline/requirements.txt`

베이스라인 실행에 필요한 Python 패키지와 버전 정보가 포함된 파일입니다.

#### `baseline/README.md`

베이스라인 설치 및 실행 방법이 포함된 문서입니다.

## 4. 공식 Submission Kit 사용 규칙

### 4.1 공식 제출킷 사용 의무

모든 제출 파일은 반드시 대회에서 제공하는 공식 `submission_kit`을 사용하여 생성해야 합니다.

```bash
cd submission_kit
python make_submission_csv.py
```

실제 실행 명령과 옵션은 `submission_kit/README.md` 및 베이스라인 코드를 확인합니다.

### 4.2 금지 사항

다음 행위는 규정 위반에 해당할 수 있습니다.

- `submission_kit` 내부 코드 수정
- 평가용 모델 수정
- 평가용 checkpoint 또는 가중치 변경
- `make_submission_csv.py` 출력 CSV 수동 수정
- 비공식 방식으로 제출 CSV 생성
- 점수 향상을 목적으로 제출 feature 또는 값을 후처리
- 공식 평가 모델의 출력값이 달라지도록 실행 환경이나 코드를 조작

특히 다음 checkpoint는 재학습하거나 파라미터를 변경할 수 없습니다.

```text
submission_kit/checkpoints/action_extractor.ckpt
```

### 4.3 제출 재현 검증

최종 수상 후보에 대해서는 제출 결과의 재현 검증이 진행될 수 있습니다.

검증 결과가 제출 내용 또는 리더보드 점수와 일치하지 않을 경우 다음 조치가 적용될 수 있습니다.

- 점수 취소
- 수상 취소
- 후순위 팀으로 수상 대상 변경

## 5. 최종 평가 및 코드 제출

### 5.1 최종 평가 방식

```text
정량 평가 100% = Private Score
```

코드 검증 과정에서 부정행위 또는 규정 위반이 발견된 경우 시상이 취소될 수 있습니다.

이 경우 코드 제출을 완료하고 검증상 문제가 없는 후순위 팀이 수상 대상이 될 수 있습니다.

| 항목 | 일정 |
|---|---|

### 5.3 코드 재현 요구 사항

제출 코드는 해당 팀의 **Private Score를 재현할 수 있어야 합니다.**

### 5.4 코드 작성 요구 사항

제출 코드에는 다음 요구 사항이 적용됩니다.

- 데이터 입출력 경로는 상대 경로로 작성
- 코드 파일 확장자는 `.py` 또는 `.ipynb`
- 코드와 주석은 UTF-8 인코딩 사용
- 라이브러리 로딩을 포함한 모든 코드가 오류 없이 실행되어야 함
- 개발 환경의 운영체제 정보 기재
- 사용한 라이브러리와 버전 기재
- 학습, 전처리, 추론, 제출 생성 과정을 재현할 수 있어야 함

### 5.5 필수 제출 파일

- Private Score를 재현할 수 있는 전처리 코드
- Private Score를 재현할 수 있는 학습 코드
- Private Score를 재현할 수 있는 추론 코드
- Private Score를 재현할 수 있는 모델 weight
- 실행 환경 및 라이브러리 버전 문서
- 추론 실행 방법 문서

> 추론 코드는 필수이며, 코드 검증에서 특히 중요합니다.

## 6. 팀 참여 규칙

### 6.1 참여 대상

- 인공지능 또는 로봇에 관심 있는 인하대학교 학부생 및 대학원생
- 팀당 최소 2명, 최대 5명

### 6.2 팀 구성 마감

```text
2026년 8월 17일 23:59
```

해당 시점까지 최소 2명 이상, 최대 5명 이내로 팀 구성을 완료해야 합니다.

### 6.3 대학원팀 분류

팀원 중 한 명 이상이 대학원생이면 해당 팀은 대학원팀으로 간주합니다.

### 6.4 재학생 자격

대회 기간은 다음과 같습니다.

```text
2026년 7월 16일 ~ 2026년 8월 20일
```

참가자는 대회 기간 동안 재학생이어야 합니다.

- 휴학생 참가 불가
- 모든 팀원은 2026년 7월 16일부터 8월 20일까지 재학생이어야 함
- 팀원 중 최소 1명은 2026년 9월에도 재학생 신분이어야 함

예를 들어 팀원이 4명인 경우:

- 4명 모두 대회 기간 중 재학생이어야 함
- 그중 최소 1명은 2026년 9월에도 재학생이어야 함

## 7. 사전학습 모델 사용 규칙

### 7.1 사용 가능한 모델

공식적으로 가중치가 공개된 사전학습 모델 중 다음 조건을 만족하는 모델만 사용할 수 있습니다.

- 로컬 환경에서 직접 실행 가능
- 모델 weight 공개
- 상업적 또는 비상업적 이용이 허용된 라이선스

허용 라이선스 예시:

- MIT
- Apache License 2.0
- CC BY
- CC BY-NC

사용 전 반드시 모델 저장소의 라이선스와 사용 조건을 확인해야 합니다.

### 7.2 API 사용 제한

원격 서버 기반 API로만 접근 가능한 모델은 사용할 수 없습니다.

사용 불가 예시:

- OpenAI API
- Gemini API
- 기타 외부 서버 기반 생성 API

모든 모델은 대회 검증 환경에서 로컬로 직접 실행 가능해야 합니다.

## 8. 외부 데이터 및 데이터 누수 금지

### 8.1 외부 데이터 사용 금지

모델 학습에는 대회에서 제공하는 데이터만 사용할 수 있습니다.

다음 데이터는 사용할 수 없습니다.

- 인터넷에서 수집한 영상 또는 이미지
- 별도의 로봇 조작 데이터셋
- 참가자가 자체 제작하거나 별도로 수집한 학습 데이터
- 외부 데이터로 생성한 pseudo label
- 평가 데이터를 기반으로 생성한 학습용 데이터

### 8.2 평가 데이터 학습 금지

`data/eval/`은 어떠한 형태로도 모델 학습에 사용할 수 없습니다.

금지되는 행위의 예:

- 평가 이미지로 모델 fine-tuning
- 평가 action을 학습 데이터에 포함
- 평가 데이터 pseudo labeling
- 평가 결과를 바탕으로 반복 학습
- 평가 샘플 통계 또는 정답 정보를 이용한 데이터 누수
- Public Score를 이용해 평가 샘플별 출력을 직접 최적화하는 방식

평가 데이터 정보 활용 또는 Data Leakage가 확인되면 수상 대상에서 제외될 수 있습니다.

## 9. 리더보드 제출 규칙

### 9.1 일일 제출 횟수

```text
1일 최대 3회
```

### 9.2 사용 가능 언어

```text
Python
```

### 9.3 파일 인코딩

모든 CSV 데이터와 제출 파일은 UTF-8 인코딩을 사용해야 합니다.

### 9.4 최종 제출 파일 선택

Private Score는 참가자가 최종 평가 대상으로 선택한 제출 파일 1개를 기준으로 계산합니다.

- 참가자는 제출 페이지에서 최종 평가 파일을 직접 선택해야 함
- 선택하지 않으면 Public Score가 가장 좋은 제출물이 자동 선택됨
- 최종 파일을 선택한 뒤 추가 제출하면 자동 선택 상태가 다시 Public Score 최고 제출물로 변경될 수 있음
- 추가 제출 후 최종 평가 파일이 올바르게 선택되어 있는지 다시 확인해야 함

## 10. 부정행위 및 코드 검증

대회 운영 중 규정 위반이 의심되면 운영진이 코드 제출을 요청할 수 있습니다.

요청을 받은 경우 다음 조건이 적용됩니다.

- 요청 후 2일 이내 코드 제출
- 미제출 시 리더보드 기록 삭제 가능
- 외부 데이터 사용이 확인되면 리더보드 기록 삭제 가능
- 제출 결과가 재현되지 않으면 점수 또는 수상 취소 가능
- 부정 제출 이력이 있는 참가자는 평가가 제한될 수 있음

## 12. 제출 전 체크리스트

### 모델 및 데이터

- [ ] 사용한 사전학습 모델의 weight가 공개되어 있다.
- [ ] 모델 라이선스가 대회 규정상 허용된다.
- [ ] 모델이 외부 API 없이 로컬에서 실행된다.
- [ ] 대회 제공 데이터 외의 외부 데이터를 사용하지 않았다.
- [ ] `eval` 데이터를 학습 또는 pseudo labeling에 사용하지 않았다.

### 생성 영상

- [ ] 모든 평가 샘플에 대해 영상을 생성했다.
- [ ] 이미지와 action의 샘플 ID가 정확히 대응된다.
- [ ] 영상 파일명이 `sample_000000.mp4` 형식을 따른다.
- [ ] 영상 파일이 `submission_kit/input_videos/`에 있다.
- [ ] 누락되거나 손상된 MP4 파일이 없다.

### 제출 파일

- [ ] 공식 `submission_kit`을 수정하지 않았다.
- [ ] `action_extractor.ckpt`를 수정하거나 재학습하지 않았다.
- [ ] `make_submission_csv.py`로 CSV를 생성했다.
- [ ] 생성된 CSV를 수동 수정하지 않았다.
- [ ] CSV가 UTF-8로 인코딩되어 있다.
- [ ] 최종 평가 대상으로 사용할 제출물을 선택했다.

### 재현 코드

- [ ] 상대 경로를 사용한다.
- [ ] 전처리 코드가 포함되어 있다.
- [ ] 학습 코드가 포함되어 있다.
- [ ] 추론 코드가 포함되어 있다.
- [ ] 모델 weight가 포함되어 있다.
- [ ] 환경과 라이브러리 버전이 문서화되어 있다.
- [ ] 단일 RTX PRO 6000에서 학습이 4일 이내 완료된다.
- [ ] 단일 RTX PRO 6000에서 전체 eval 추론이 1시간 이내 완료된다.
- [ ] 제출한 Private Score를 재현할 수 있다.

## 13. 핵심 주의 사항 요약

1. **점수는 낮을수록 좋습니다.**
2. **Action Component의 비중이 0.4로 가장 높습니다.**
3. **외부 데이터와 평가 데이터 학습은 금지됩니다.**
4. **원격 API 기반 모델은 사용할 수 없습니다.**
5. **제출킷과 평가 checkpoint는 수정할 수 없습니다.**
6. **제출 CSV는 반드시 공식 `make_submission_csv.py`로 생성해야 합니다.**
7. **생성된 CSV를 직접 수정하면 안 됩니다.**
8. **영상 파일명과 평가 샘플 ID가 정확히 일치해야 합니다.**
9. **전체 eval 추론은 단일 RTX PRO 6000에서 1시간 이내여야 합니다.**
10. **최종 수상 후보는 학습·추론·제출 결과를 재현할 수 있어야 합니다.**
