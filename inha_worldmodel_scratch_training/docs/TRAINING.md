# 학습 설명 — 입력과 손실

SO-100 액션 조건 영상 생성. 초기 프레임 1장 + 16스텝 6축 관절 명령 → 16프레임 영상.
점수(낮을수록 좋음) `0.3 × DINO + 0.3 × Video(r3d_18) + 0.4 × Action MAE`.

Action MAE 는 주최측이 **우리 생성 영상을 자기네 역동역학 모델에 넣어** 액션을 역추정하고
정답과 비교한 값이다. 그래서 목표는 예쁜 영상이 아니라 **명령이 되읽히는 영상**이다.

---

## 1. 무엇을 학습하나

```
Cosmos-Predict2.5-2B (action-cond)   20억 파라미터 — 전부 동결
  + LoRA r32 / alpha32                280개 모듈
  + 액션 임베더 전체                    fc1 은 새로 초기화, fc2 만 사전학습 계승
  ─────────────────────────────────
  학습 대상 113.4M (전체의 5.7%)
```

LoRA 대상은 `q_proj`·`k_proj`·`v_proj`·`output_proj`(각 56개)와 MLP `layer1`·`layer2`(각 28개).

액션 임베더를 통째로 학습하는 이유는 **차원이 안 맞아서**다. 사전학습 임베더는 7축용,
SO-100 은 6축이다. 그래서 액션 경로는 사실상 처음부터 배운다.

## 2. 입력 — 모델 호출에 들어가는 것

```python
net(
    x_B_C_T_H_W                = xt,                          # (B,16,5,40,64)  잡음 섞인 잠재
    timesteps_B_T              = t * 1000,                    # (B,1)           잡음 세기
    crossattn_emb              = text_emb.expand(B,-1,-1),    # (B,512,100352)  빈 문자열, 전 샘플 동일
    condition_video_input_mask = cond_mask,                   # (B,1,5,40,64)   0번 프레임만 1
    fps                        = 6,
    padding_mask               = zeros,
    action                     = act_in,                      # (B,16,6)        z정규화 관절각
)
```

### 2.1 영상 → 잠재

```
mp4 640×480 (6fps)
  → letterbox 320×512      scale = min(320/480, 512/640) = 0.667
                           실제 화면은 427×320, 좌우 42px 씩 검은 띠
  → 17프레임 창             1장은 조건, 16장이 생성 대상
  → WanVAE 인코딩           공간 8배 / 시간 4배 압축
  → (16, 5, 40, 64)        잠재 5프레임 = (17−1)/4 + 1
```

17 이 되는 이유: 대회가 16프레임을 요구하고, 초기 프레임 1장이 조건으로 주어지고,
시간 압축비가 4라 `(T−1)/4+1` 이 정수로 떨어지는 값이 17 이다. 16 이나 18 은 어그러진다.

잠재는 매 학습 스텝마다 만들지 않는다. **104,828 개 창을 미리 전부 인코딩해 디스크에
저장**해 뒀다(40GB). 학습 중에는 작은 텐서만 읽는다 — mp4 도 VAE 도 건드리지 않는다.
덤으로 학습과 추론이 같은 인코딩 경로를 쓰는 것이 보장된다.

### 2.2 액션

```
원본 관절각(도) (16,6)
  → z 정규화   (act − mean) / std          train 통계만 사용
      mean = [  3.0, 117.6, 109.8,  61.7, −29.4,  9.8]
      std  = [ 26.4,  50.2,  46.6,  29.7,  62.6, 16.4]
  → 그대로 net(action=...)                 DELTA=0, ABS_AUG=0, ACT_DROP=0 이면 가공 없음
```

### 2.3 액션이 모델 안에서 도달하는 곳

```
action (B,16,6)
  → rearrange (B,4,24)            연속 액션 4개를 24차원 하나로 뭉침
  → Mlp(24 → 8192 → 2048)   → 타임스텝 임베딩에 가산
  → Mlp(24 → 8192 → 6144)   → adaLN 변조에 가산 (28블록 전부의 정규화 조절)
```

**액션의 유일한 도달 경로가 adaLN 이다.** `t_embedding_B_T_D` 는 (B,T,D) — 잠재 프레임
하나당 벡터 하나이고, 그 프레임의 20×32 = 640 개 공간 토큰 **전부에 동일하게 브로드캐스트**된다.
즉 "이번 프레임 전체를 이만큼" 은 말할 수 있어도 "화면 이 위치의 그리퍼를 이쪽으로" 는
원리적으로 못 말한다.

크로스어텐션 경로(`crossattn_emb`)는 빈 문자열 임베딩 파일 하나를 전 샘플에 그대로 쓴다.
샘플별 정보량이 정확히 0 이다.

### 2.4 조건 프레임

```
cond_mask[:, :, 0] = 1.0
xt = x₀ * mask + xt * (1 − mask)      0번 잠재 프레임은 항상 깨끗한 정답으로 덮는다
```

`UNCOND_P = 0.0` 이라 CFG 드롭아웃 분기는 걸리지 않는다.

## 3. 손실 — 매 스텝 셋 중 하나

```python
draft_step = draft and (rand() < DRAFT_P)                  # 기본 0.5
aux_step   = (not draft_step) and aux and (rand() < P_AUX) # 기본 0.3
```

연속한 두 스텝이 서로 다른 목적함수로 학습된다.

### 3.1 흐름정합 (기본)

```
t_raw = sigmoid(randn)
σ     = 5·t_raw / (1 + 4·t_raw)              SHIFT=5 로 높은 쪽에 몰림
xt    = (1−σ)·x₀ + σ·noise
xt[0] = x₀[0]
v_target = noise − x₀
rf_loss  = mean[(v_pred − v_target)²]        ← 0번 프레임은 분모에서 제외
```

σ 가 높은 쪽에 몰리는 것이 핵심이다. `t_raw=0.5` 면 실제 σ 는 0.83 이다.
**학습 시간의 대부분을 "거의 안 보이는 상태에서 복원하기" 에 쓴다.**

0번 프레임을 손실에서 빼는 이유: 조건으로 받은 것을 다시 맞히는 데 학습을 쓰지 않는다.

### 3.2 판독기 벌점

```
σ = uniform(0.05, 0.45)                      ← 낮은 쪽만
x₀_pred = xt − σ·v_pred                      예측 속도로 원본 복원
aux_l1  = mean| 판독기(x₀_pred) − act |
total   = rf_loss + W_AUX · ramp · aux_l1    W_AUX=0.3
```

σ 범위가 다른 이유: 잡음이 세면 복원된 `x₀_pred` 에 형체가 없어 판독기가 읽을 게 없다.

판독기(`runs/latent_idm2/lidm2_best.pt`)는 **동결**이다. 대회 train 잠재와 정답 액션만으로
우리가 직접 학습했고(`train_latent_idm2.py`), 제출킷의 모델·코드·가중치와 무관하다.

액션 드롭아웃은 이 스텝에 걸지 않는다 — `act` 가 벌점의 정답이라 입력을 널로 두면
"없는 액션을 복원하라" 는 모순이 된다.

### 3.3 DRaFT

```
s₀   = uniform(0.35, 0.65)
xcur = (1−s₀)·x₀ + s₀·noise,  xcur[0] = x₀[0]
s₀ → 0 을 3등분해 오일러 전개
     앞 2스텝 무기울기, 마지막 1스텝만 미분   ← 전체 미분은 29GB OOM (로컬 16GB)
reward = mean| 판독기(xcur) − act | × 관절가중
anchor = mean| xcur − x₀ |
total  = W_R·reward + W_ANCHOR·anchor        둘 다 1.0
```

앞의 둘은 "한 걸음 앞 맞히기" 연습이다. 여기서는 실제로 영상을 만들어보고 그 결과로 학습한다.

**앵커가 없으면 무너진다.** 보상만 주면 모델이 "판독기가 좋아하는 무언가" 로 도망가는데
그게 영상일 필요가 없다. 앵커가 원본에서 멀어지지 못하게 묶는다.

### 3.4 갱신

```
(total / 8).backward()
8개째마다 → clip_grad_norm(1.0) → opt.step()
BATCH=1, ACCUM=8 → 유효 배치 8
```

`BATCH=1` 은 필수다. 잠재 모드 기본값 2 는 16GB 를 넘겨 Windows 가 시스템 RAM 으로
밀어내면서 **죽지 않고 40배 느려진다**(1.24 → 60.7초/스텝).

### 왜 이렇게 바꾸나

**커버리지** — 챔피언은 중복 뽑기라 10만 창 중 54% 만 봤다. 창이 9프레임씩 겹치므로
프레임 단위로는 73% 지만, **처음부터 끝까지 다 본 에피소드는 10,735개 중 18% 뿐**이다.
`replacement=False` 로 두면 커버리지가 100% 가 되고, 이때 가중치는 순서에만 관여하므로
움직임 편향도 함께 사라진다.

**움직임 편향** — 챔피언은 `MOTION_POW=1` 로 움직임 큰 창을 최대 3배 자주 봤다.
그 결과 학습이 실제로 본 움직임이 데이터 평균의 **140.2%** 다.
그리고 val 클립 16개에서 정답과 나란히 재보니 생성물 움직임이 정답의 **149%**(14/16 과잉)였다.
두 숫자가 비슷하지만 **이건 상관이지 인과가 아니다.** 이 프로젝트는 정확히 이런 식으로
한 번 졌다(균등 샘플링, 0.1964). 그래서 편향을 0 까지 내리지 않고 절반만 되돌린다.

**시드** — 챔피언까지 모든 학습에 샘플러 시드가 없었다. 같은 설정으로 다시 돌려도 다른
창을 뽑았다는 뜻이다. 그래서 8번의 가중치 실험이 왜 실패했는지 원인까지 가르지 못했다.

**DRaFT 를 끝에 남기는 이유** — 3스텝 전개로 실제 영상을 만들어 판독기로 채점하는 방식이다.
step 0 에서 LoRA 는 0 초기화라 모델이 로봇팔을 전혀 모르고, 만들어지는 건 쓰레기이고,
그 보상은 순수 잡음이다. 벌점은 가중치 램프로 피할 수 있지만 DRaFT 는 켜고 끄는 것이라 못 피한다.

### 판정

A끝 · B끝 · soup · D끝 **네 지점을 전부 제출한다.** 챔피언도 같은 자리에 대응 지점이 있어
구간별 비교가 된다. 이 프로젝트에서 단발 제출은 8전 8패였고, 무언가를 알려준 것은
언제나 곡선이었다.

## 7. 알려진 한계 — 팀원이 알아야 할 것

**판독기는 처음 보는 장면에서 무너진다.**

| 대상 | 판독기 MAE |
|---|---|
| 실제 잠재 (val) | 0.1069 |
| val 생성물 | 0.23 |
| **eval 생성물** | **0.7555** (상수예측기 0.7470보다 나쁨) |

val 은 train 과 같은 책상·같은 카메라의 다른 회차라 잘 읽고, eval 은 처음 보는 장면이라
실패한다. 학습 중 벌점은 train 과 비슷한 장면에서만 의미 있는 신호다.
**판독기를 선택기로 쓰는 모든 형태(BoN)는 영구 폐기**다 — LB 0.2126 으로 크게 실패했다.

**val 손실은 리더보드로 이전되지 않는다.** 3회 실증됐고 오히려 역상관이었다.

| 체크포인트 | val loss | LB |
|---|---|---|
| 챔피언 | 0.10464 (가장 높음) | **0.1872** (가장 좋음) |
| 챔피언 +20k | 0.10372 | 0.2166 |
| 균등 200k | 0.09747 (가장 낮음) | 0.1964 |

원인 중 하나로 의심되는 것: **val 분할이 과제 단위가 아니라 에피소드 단위**다.
val 에피소드는 train 과 같은 폴더의 다른 회차라 사실상 같은 분포다.

**그래서 채택 판정은 리더보드 총점으로만 한다.** val 손실, 판독기 점수, 임베딩 통계,
오프라인 분포 정렬 — 어느 것도 채택/폐기 근거로 쓰지 않는다. 학습 중 계측은
"경로가 살아 있나" 만 보는 디버깅 신호이지 품질 판정이 아니다.

**추론 화질의 상한은 이미 거의 닿아 있다.**

- 원본이 6fps 라 정답 영상 자체가 뚝뚝 끊긴다
- letterbox 로 640×480 → 427×320, 원본 화소의 44.5% (제출킷 전처리와 동일)
- VAE 왕복 PSNR 37.80 dB, 잠재프레임 경계에 오차 스파이크 없음 → VAE 는 병목이 아니다
- 팔 영역 국소 선명도는 정답의 99%(중앙값), 다만 클립별 산포가 63~118% 로 크다

즉 점수의 60% 인 DINO·Video 항목에서 우리가 더 짜낼 여지는 크지 않다.
남은 것은 **움직임 크기**이고, 그건 추론에서 액션 배율(β)로 학습 없이 검정할 수 있다.

## 8. 규정

- 제출킷은 **최종 mp4 확정 후 CSV 변환에만, 무수정 1회** 실행한다.
  학습·추론·후처리 어디에도 킷의 모델·코드·checkpoint 를 쓰지 않는다.
